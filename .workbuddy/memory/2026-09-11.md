## 第三份豆包分析（P0' 交互成熟度）—— 核实与纠正

来源：豆包 thread `xfLQpBALjZuUBH1uS`，随后又一份「P0' 五项交互成熟度」清单。核心断言是「下拉刷新/骨架屏/触觉反馈/转场动画 全仓 0 实现，交互成熟度为零」。

**核实方法（关键）**：业务代码搜关键词只能证明「业务没用」，不能证明「能力不存在」。框架源码包在 Gradle 缓存里可解压核对：
`~/.gradle/caches/modules-2/files-2.1/com.tencent.kuikly-open/core/2.7.0-2.1.21/<hash>/core-2.7.0-2.1.21-sources.jar`
解压后路径前缀为 `commonMain/com/tencent/kuikly/core/...`。

**结论：5 项里只有 1 项是真缺**

| 能力 | 分析判断 | 实测 | 证据 |
|---|---|---|---|
| 下拉刷新 | 缺失 | **框架自带** | `views/RefreshView.kt`：`ScrollerView.Refresh { }`，`refreshEnable`，`refreshStateDidChange`，`pullingPercentageChanged`，`beginRefresh(animated)`；状态 IDLE/PULLING/REFRESHING |
| 触底自动加载 | 缺失 | **框架自带** | `views/FooterRefreshView.kt`：`beginRefresh()` / `endRefresh(endState)`，`preloadDistance` 默认 100f（**预加载**，不是到底才请求） |
| 动画/转场 | 显示 0 匹配 | **框架自带** | `base/Animation.kt`：`Animation.linear/easeIn/easeOut/easeInOut/spring*` + `delay/repeatForever`；`base/attr/IStyleAttr.kt:115,125`：`animation(anim, value)` / `animate(anim, value)`；另有 `views/TransitionView.kt` |
| 骨架屏 shimmer | 缺失 | **可用现有原语自建** | 无现成组件，但 `Animation.repeatForever(true)` 足够做 shimmer |
| 触觉反馈 | 缺失 | **真缺** | commonMain/iosMain 全库搜 `vibrat/haptic/impactFeedback/震动` = 0；`core/module/` 下 17 个内置 Module 无此类。需自定义 Module（项目已有先例 `base/BridgeModule.kt`）+ Android Vibrator / iOS UIImpactFeedbackGenerator 双端原生实现 |

**注意**：`transition` 关键词 0 匹配是同义问题——框架里叫 `TransitionView`。这类「搜索词不对导致误判」是本项目反复出现的坑。

**另一处纠正**：StockDetailPage 现为 **4195 行**（分析写 3881，已过时且仍在增长）。

**关于骨架屏的独立判断**：主数据路径是本地 JSON（`JsonBackedStockDb.stockDetail(code)` 是非 suspend 同步读取，无网络），骨架屏会 0ms 闪一下 = 纯摆设。只在 **AI 分析面板 / 聊天**（走 DeepSeek 网络请求）才有真实价值。

**另一处可复用线索**：`KlineChartInteraction.kt:107` 已有 `InteractionState.Hover(globalIdx)` 状态机；Kuikly 另有 `views/HoverView.kt`（`ScrollerView.Hover { }`）。分时补 Hover 跟随态可与「分时对齐 K 线交互」合并为同一件事做。

**页面滚动容器现状**（决定接入成本）：列表页大量用 `List(`，详情/首页用 `Scroller {`。两者正好分别对应 `FooterRefreshView` 与 `RefreshView.Scroller` 的宿主，属**接线**而非**造组件**。

## P0' 交互成熟度落地（4 项，已在真机验证）

分支 `feat/p0-chart-ux`。改动 7 个文件 + 新增 2 个（`ListRefresh.kt` / `ChartAnimation.kt`），221 增 132 删。

### 1. 下拉刷新（`ListRefresh.kt` + 3 个页面）
- Kuikly `RefreshView` **不自带 UI**：不给 `height()` 它 `layoutFrame.height == 0f` 会直接在 `onContentOffsetDidChanged` 里 return，状态回调永不触发。这是最容易踩的坑。
- `RefreshView.scrollerView = (parent?.parent as? ScrollerView)` —— **必须放在 Scroller 的第一个子视图位置**，中间不能再包容器。
- 它是 `positionAbsolute`，作为第一个子视图处于**最底层**，被后续内容盖住；下拉时才露出 —— 这是正确的实现方式，不会遮挡首行内容（真机确认）。
- 用 `ref { ctx.pullRefreshRef = it }` 拿 `ViewRef<RefreshView>`，完成时 `pullRefreshRef?.view?.endRefresh()`。
- 接入页面：`StockListPage`（下拉时走静默模式，不弹 hint 气泡）、`WatchlistPage`、`HomeDashboardPage`（下拉=force 刷新）。
- **务必处理早退路径**：原有 `if (isLoading) return` 会让刷新头永远转下去，必须在该分支也调 `endRefresh()`。

### 2. 触底自动加载（替代「加载更多」按钮）
- `FooterRefreshView` 的 `scrollerView` 是**沿 parent 向上遍历**找 `ScrollerView`，所以放哪层都能找到 —— 和 RefreshView 不同，不需要放在首位。
- `preloadDistance(200f)`（默认 100f）+ `refreshStateDidChange` → 状态转 `REFRESHING` 时触发取数。
- 取完必须 `endRefresh(SUCCESS)`；无更多数据时必须 `endRefresh(NONE_MORE_DATA)`，否则会反复触发。
- 重新拉取时（isRefresh）要 `resetRefreshState(IDLE)`，否则停在 NONE_MORE_DATA 不再触发。
- 已删除 `loadingMoreView` / `loadMoreButton` / `noMoreButton` 三个死函数。

### 3. 缩放/平移动画化（`ChartAnimation.kt`）
- **关键认知**：K 线是 Canvas 手绘，`attr.animate(Animation, value)` 只作用于**视图属性**，对 Canvas 绘制内容无效。所以用协程逐帧改写 observable 视口参数，由响应式系统触发重绘。
- 实现：`Pager.tweenChartViewport(...)`，16ms/帧 × 200ms ≈ 12 帧，`easeOutCubic`，`isCancelled` 用自增序号实现「后来者作废前者」，避免连点按钮打架。
- 注意 `com.tencent.kuikly.core.coroutines.delay` 接收 **Int 毫秒**，不是 Long。
- `StockDetailPage` / `IndexDetailPage` 的 `zoomIn/zoomOut/panLeft/panRight` 统一改为 `animateZoom` / `animatePan` + `animateViewport`。
- 真机验证：23根→10根（下限）→23根（上限），**补间精确落在 clamp 后的终值**，连点 0.5s 间隔也正确逐步推进。

### 4. 分时手势对齐 K 线（`ChartTouchLayer.kt` + 接口）
- 原实现：`if (kind != "pinch" && state != "cancel") ctx.selectMinuteAtX(x)` —— 完全忽略 `kind`，长按 = 单击。
- 新语义：`tap` → 锁定（再点同一点取消）；`pan`/`range` 的 start/move → 跟手查看（locked=false）；`end` → 抬手保留锁定；`cancel` → 清除。
- 接口变更：`selectMinuteAtX(x: Float)` → `selectMinuteAtX(x: Float, locked: Boolean)`，新增 `clearMinuteSelection()`（IndexDetailPage 空实现）。
- 新增 observable `minuteLocked`，控制条芯片文案随状态切换：拖动时「跟手查看中」，锁定后「已锁定 · 清除」。
- 真机验证：单击→「已锁定 · 清除」；拖动中间帧→「跟手查看中」；再点同一点→清除。

**三个必须知道的坑**：

### #7 iOS/JS 指数·板块·资金流数据兜底（新增导出契约）
问题：Android 走 SQLite `stock.db`，iOS/JS 走 `JsonBackedStockDb`，后者 `indexDetail()` 直接 `return null`，
`industryPeers()/sectorOfStock()/fundFlow()` 返回空 → 指数详情页在双端"有壳无肉"。

方案：新增 `data-pipeline/export_common_assets.py`，从 `stock.db` 导出内置资产到 `shared/src/commonMain/assets/`：
- `index_list.json`、`fundflow_list.json`
- `sector_list.json`（559.8KB：236 板块 / 11283 成分股 / 5528 个股映射）

**关键决策**：`sector_list.json` 内嵌 `stock_board` 直连映射（code→board_code）。
原因是 `stock_list.json` 是**人工裁剪的旧快照**（5212 条 vs DB 5911 条，价格为 8-25 vs 9-09），
无生成脚本、不可复现，其行业词表已漂移（旧"银行Ⅱ" vs 新"股份制银行Ⅲ"），
若沿用行业名 JOIN 会选错板块（校验脚本实测抓到 26 项不一致）。固化映射后 iOS/JS 不再依赖行业词表。
**stock_list.json 保持不动**，只在新增资产里规避。

配套：`test_export_common_assets.py`（8 个单测，逐字段比对 JSON 解码 vs SQLite 查询）、
`run_daily.ps1` 加 `[1b/3] 导出内置 JSON 资产` 步骤、CI `build.yml` 增 `data-assets` job。

### #8 指标缓存与增量重绘

### #9 触觉反馈（自建双端原生桥）
框架 core 2.7.0 内置 17 个 Module 无一提供震动 API → 复用宿主已有的 `HRBridgeModule` 扩方法（不动 xcodeproj）。
- common：`base/Haptics.kt`（`HapticStyle` 三档 + `hapticTick()`，`runCatching` fire-and-forget）
- Android：`KRBridgeModule.vibrate()`，`VibrationEffect.createOneShot`（light 12 / medium 24 / heavy 40ms），<26 回落老 API
- iOS：`HRBridgeModule.m -vibrate:`，`UIImpactFeedbackGenerator`（主线程 dispatch）
- JS：无原生实现，走空操作

触觉词汇表（K 线/分时统一）：Medium=落点锁定（tap）、Heavy=模式切换（长按进框选）、
Light=收尾（框选结束 / 抬手落定 / 切周期 / 切副图 / 列表点击 / 下拉刷新）。
平移（未锁定拖动）**不震**，否则持续震动。共 11 个调用点。

## 诊断：甲方说「交互更像原型一些」到底指什么

甲方原话：「整体比之前好不少，主要指是一些交互 更像原型一些」。
**结论：「原型感」不是功能少，而是"状态机太浅"** —— 原型只有 `意图 → 结果` 两态，
产品级在中间垫了 `确认 / 过程 / 稳定` 等可见过程。

### 量化证据（本次实测，可直接用于 PR/汇报）
| 维度 | 现状 | 说明 |
|---|---|---|
| 点击反馈 | **150 处 `click`，0 处按压态** | 全仓搜 `highlight/touchDown/pressed/ripple` 无关命中（那些是图表 AI 价位高亮） |
| 加载过程 | **6 处全是纯文字「加载中...」** | StockDetailKline:364 / Minute:81 / OrderBook:49 / Views:204 / StockList:662 / Watchlist:370 |
| 内容动画 | **框架 `Animation` API 使用 0 次** | 唯一动画是 Canvas 自绘的 `tweenChartViewport`（ChartAnimation.kt，StockDetailPage:558 / IndexDetailPage:274） |
| 骨架屏 | **0** | 全仓搜 skeleton/shimmer = 0 文件 |
| 空态 | 有文案（10+ 处），但都是"一句话 + 无出口" | 缺"去更新/去设置"这类引导动作 |
| 数据新鲜度 | **有，34 处时间标注** ✅ | dataSourceFooter / analysisDateLabel，这块合格 |

### 三条病灶与改法
1. **无按压形变（最致命）**：150 处 click 无视觉反馈，用户只能靠"松手后跳转"反推点中了。
   → 抽 `tappable { }` 包装器（内部管按下/抬起 + 背景变化 + 复用已有 `hapticTick`），把列表项/按钮/页签换过去。
2. **加载是文字不是版式**：`加载中...` 让内容在数据到达前后位置完全不同。
   → 做 `skeletonBlock(w,h)` 基元，替换 6 处文字。骨架屏核心价值是"先占住版式、不跳"。
3. **一切瞬变**：切周期 K 线瞬换、AI 卡片瞬现、数字直接替换。
   → 抽 `tweenNumberTo` / 内容区淡入，时长对齐已有 `CHART_TWEEN_MS = 200`。

### 两条纪律（重要）
- **动效要克制**：只做"状态切换"过渡（180–220ms），不做装饰性动画（弹跳/发光/飞入）。做过头会更假。
- **别去刷视觉**：甲方说的是**交互**不是视觉。改配色/阴影/圆角不会改变这个评价。

## 十、按压态 + 骨架屏样板落地（用户回复"需要"，已动手）

### 先做的调研（结论推翻了上一轮的部分判断）
- **框架有按压态能力**：`View` 的事件对象是 `DivEvent : GroupEvent`，`GroupEvent`
  公开了 `touchDown / touchUp / touchCancel`（模块 `views.internal.GroupEvent`）。
  框架自己的 `ButtonView` 就是用这套做高亮。
- **`attr { }` 是响应式的**：`DeclarativeBaseView.attr()` 内部包了
  `ReactiveObserver.bindValueChange` → **attr 块里读到的 observable 一变，整个
  attr 块自动重跑，并把新值下发成 native prop**（`Props.setProp` 会跳过无变化的 prop）。
  这一条是按压态能"零原生代码"实现的关键。
- **框架自带 `GroupAttr.highlightBackgroundColor(color)`**：会自动插一个绝对定位
  高亮层并注册 touchDown/Up。但它只被官方 demo 用在 `Button` 上；KDoc 有警告
  "若手指按下区域存在其他手势（如 Click），则不会触发高亮"——经查 Android 侧
  `KRView` 默认走 `onTouchEvent` 分支派发触摸，被子视图消费即不触发，故未采用。
- `superTouch` 在 Android / iOS 语义相反（Android 走 dispatchTouchEvent 分支、
  iOS 走手势驱动并**抑制** touch 回调），是个跨端陷阱，本次刻意不碰它。

### 新增文件
- `shared/src/commonMain/kotlin/com/kuikly/stock/base/Interaction.kt`
  - `PressState(scope: PagerScope)`：一个页面一份，内部 `key` 由 `scope.observable("")` 驱动。
    同一时刻只可能有一个元素被按下（单指约束），所以用单个 key 而不是每元素一份状态。
  - `Attr.pressedBg(press, tag, normal, pressed)`：在 `attr { }` 里声明按压底色。
  - `GroupEvent.pressFeedback(press, tag)`：在 `event { }` 里注册按下/抬起/取消三段式。
    刻意不发触觉——调用点的 `click` 已有 `hapticTick`，否则会"按下震一下、松手又震一下"。
  - `ViewContainer<*,*>.skeletonBlock(height, w, radius, color)`：灰块占位基元。
  - 常量：`PRESS_BG_LIGHT=0xFFE8EBEF` / `PRESS_BG_DARK=0x33FFFFFF` /
    `PRESS_BG_NONE` / `SKELETON_BG` / `SKELETON_BG_STRONG` / `SKELETON_BG_ON_DARK`。
    **必须显式标 `: Long`**：`0x33FFFFFF`、`0x59FFFFFF` 落在 Int 范围内，不标会被推成 Int
    导致 `backgroundColor(Long)` 调用点报 "actual type is Int, but Long was expected"。

### 接入的两个样板

### 🔴 顺手抓到一个会崩进程的存量 bug（上一轮触觉反馈埋的）
- 现象：点列表项 → `FATAL EXCEPTION: HRContextQueueHandlerThread`，
  `RuntimeException: acquireModule 失败：HRBridgeModule 未注册`。
- 根因链：
  1. `BasePager.createExternalModules()` 是唯一注册 `BridgeModule` 的地方，
     但它是 `internal`，而 10 个页面都是 public `class X : Pager()` —— **public 类
     无法继承 internal 超类**，所以从来没有任何页面继承它，模块**从未注册过**。
     （`RouterPage` / `ImageAdapterBenchmarks` 是 internal，确实继承了，这也是
     `BasePager` 当初被标 internal 的原因。）
  2. `Pager.acquireModule` 模块缺失时调 `throwRuntimeError`，而它的实现是
     `setTimeout(1) { throw … }` **外加** 立即 `throw`。`runCatching` 只能接住立即那次，
     延迟那次 1ms 后在定时器线程上把进程打崩。
  3. 所以 `hapticTick` 的"兜底"是假的：**触觉反馈一次都没生效过，且每次调用都崩。**
- 修复（两层）：
  - `BasePager` 改为 **public** 且只保留 `createExternalModules`（去掉原先无关的
    夜间模式 / debugUIInspector override，避免接入后引入行为变化）；
    10 个页面全部改继承 `BasePager`（脚本批量改，附 import）。
  - `Utils.currentBridgeModuleOrNull()`：走 `Pager.getModule`（返回 null，不抛）+
    `runCatching` 包住 pager 查找；`hapticTick` 改用它。
- 实测确认修复：`dumpsys vibrator_manager` 出现
  `usage: TOUCH | com.kuikly.stock | played: Step=12ms`（正是 light 档），且 crash buffer 为空。

### 验证手法上的两个教训（已写进 skill）
- **`input swipe x y x y 1200` 按不住**：零距离 swipe 不产生持续按下态，
  抓到的帧没有高亮。必须用 `input motionevent DOWN/UP` 才能精确控制按下与抬起。
- **不能用肉眼看缩略图判断细微变化**：`#FFFFFF→#E8EBEF` 在缩略图里几乎看不出，
  我第一次据此误判"按压态没生效"。改用像素 diff（包围盒 + 变化行段 + 颜色采样）
  才得到确定结论。反向也成立：状态栏时钟变化会让两帧不同，只看 hash 会误判"有变化"。
- Git Bash 里 `adb exec-out screencap > /tmp/x.png` 会静默失败、`/c/...` 路径
  native Python 读不了 —— 截图目录用 `$HOME/AppData/Local/Temp`，给 Python 传
  `C:/...` 形式路径。
